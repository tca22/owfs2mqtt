# ADR-0012: DS2413 dual I/O representation

- Status: Accepted
- Date: 2026-08-29
- Scope: OWFS/OWServer → MQTT V3

## Context

The DS2413 is a dual-channel addressable switch (family `3A`). OWFS exposes the switch state through `PIO.A` and `PIO.B`. The project must expose these two channel states without requiring physical hardware during development.

OWFS provides a fake adapter specifically for software testing. `--fake=3A` creates a simulated DS2413 with random device identity and values; the related tester adapter provides predictable values when deterministic OWFS-level testing is required.

## Decision

OW2MQTT reads and publishes the DS2413 switch states as:

- `PIO_A`
- `PIO_B`

The implementation may also expose `PIO_ALL`, `PIO_BYTE`, `sensed_A` and `sensed_B` when available, but `PIO_A` and `PIO_B` are the required application values.

FHEM presentation is defined separately from the MQTT protocol. The intended FHEM device STATE is a compact representation of both channels:

`A: <PIO_A> | B: <PIO_B>`

No physical DS2413 is required for the software test suite. An OWServer instance using `--fake=3A` is the preferred integration test once available.

## Consequences

- DS2413 support can be tested before hardware is available.
- MQTT remains a neutral representation of the two switch channels.
- The FHEM STATE is a presentation concern and does not alter the MQTT payload.
- Fake-adapter values are random, so the integration test must validate structure and value domain rather than fixed values.
